# Changelog

Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/), версии —
[SemVer](https://semver.org/lang/ru/). Единственный источник версии — файл
`VERSION` в корне; поменять: `scripts/version.sh set X.Y.Z`.

Пока `0.x` — API `/api/v1` и формат `state/` могут меняться без обратной
совместимости. Пре-релизы: `-alpha.N` — тестовые сборки для стенда,
`-beta.N` — на роутере, `-rc.N` — кандидат.

## [Unreleased]

## [0.2.0-beta.3] — 2026-09-26

Подбор стратегий nfqws2 на Pi: плагины в контроллере, плагин GP, вкладки «Прогоны»,
«Результаты», «Стратегии» и применение найденной стратегии на роутере — кнопкой, с копией
конфига и откатом. Только в полной версии: лёгкий веб на роутере этого не содержит.
Инструкция — [`docs/BETA.md`](docs/BETA.md), этап 3б.

**Обновление с 0.2.0-beta.2:** на Pi — `git pull && sh deploy/pi/bootstrap.sh` (образ
контроллера собирается заново, первый раз дольше); на роутере — инсталлятор: шаг
nuxk-core покажет «0.2.0-beta.2 → 0.2.0-beta.3», вместе с ним обновятся init-скрипт,
адаптер nfqws2 (он нужен для применения стратегий) и веб; `nuxk.conf` остаётся как есть.

### Added
- **Плагины в контроллере на Pi — в том же контейнере, без новых.** Контейнер стартует
  с `nuxk-controller supervise` (root): он запускает веб/API от `nobody` без прав, а
  каждый плагин — root без права читать чужие файлы и чужую память, только с правами
  из его `plugin.json`. Секреты контроллера (пароль администратора, ключ к роутеру)
  плагину недоступны — проверено на Pi. Установка, обновление по кнопке с выбором
  версии из релизов, автоматический откат версии, которая не запустилась, журналы.
  Раздел «Плагины».
- **Плагин GP — подбор стратегий nfqws2** (GP Access Control Plane: blockcheck2 из
  zapret2). При установке скачивает на Pi ядро GP с его тега, Python-зависимости по
  хешам из его lock-файла и zapret2 из релиза со сверкой sha256 каждого бинарника.
  Заводской пароль GP контроллер сразу меняет на случайный; из панели доступны только
  нужные вызовы API GP.
- Вкладки **«Прогоны»** (домены из списков nuxk или свои, режим, глубина, протоколы,
  прогресс и живой лог, остановка), **«Результаты»** (история прогонов) и
  **«Стратегии»** (найденные кандидаты) — вместо заглушек.
- **Применение стратегии на роутере** — только кнопкой, с объяснением: отдельный
  профиль nfqws2 для выбранных доменов в `NFQWS_ARGS_CUSTOM` (перед вашими
  стратегиями), копия `nfqws2.conf.nuxk-bak` (и однажды — оригинал `.nuxk-orig`),
  перезапуск nfqws2; если он не поднялся — прежний конфиг возвращается сам. Свои
  аргументы в `NFQWS_ARGS_CUSTOM` nuxk не перезаписывает. Агент:
  `GET/PUT /api/v1/engines/{kind}/strategies`; в конфиг попадают только
  `--payload / --lua-desync / --out-range / --in-range` без файлов и символов оболочки.
- Подбор стратегий и плагины — **только в полной версии (контроллер на Pi)**. В
  лёгкой, которая ставится на роутер без Pi, нет ни вкладок «Прогоны», «Результаты»,
  «Стратегии», «Плагины», ни их кода (веб на роутере стал меньше: 128 КБ вместо
  163); на сам роутер плагины не ставятся никогда.

### Changed
- Образ контроллера — Debian slim с Python и сетевыми утилитами для плагинов
  (~314 МБ вместо лёгкого Alpine); в compose у контейнера права, которые `supervise`
  раздаёт плагинам, `/run` и `/tmp` в памяти, `init`.

### Fixed
- **Графики прокручиваются, а не сжимаются**: ось X — время в окне фиксированной
  ширины, новые точки входят справа и уезжают влево; пауза в данных — разрыв линии,
  а не прямая через неё. На контроллере — окно «10 мин / 1 ч» (выбор запоминается в
  браузере), на часовом окне столбики NFQUEUE усредняются по 30 с. Мини-графики в
  карточках движков идут по тому же времени.
- На графике «Трафик по туннелям» больше нет служебного `tunl0` (IPIP-интерфейс ядра,
  трафика на нём не бывает).

## [0.2.0-beta.2] — 2026-09-26

Вход по логину и паролю вместо токена, мастер настройки контроллера и исправления
после первого осмотра живого роутера. Инструкция — [`docs/BETA.md`](docs/BETA.md).

### Added
- **Вход по логину и паролю вместо токена.** Панель роутера — логин `root` и пароль
  Entware (тот же, что для SSH; сверяется с `/opt/etc/shadow`), контроллер на Pi —
  `admin`. Сессия в HttpOnly-cookie, 12 часов без действий; после 5 неверных паролей
  с одного адреса вход ненадолго блокируется (до 15 мин). `API_TOKEN` остаётся только
  для программ.
- **Мастер первичной настройки контроллера**: пароль администратора → подключение
  роутера по адресу и паролю root (роутер выдаёт контроллеру ключ через
  `POST /api/v1/auth/pair`, пароль root нигде не хранится) → готово. В «Системе» —
  «Сменить роутер» и «Выйти».
- «Списки» и «Требует внимания» находят **склеенные домены** (две строки без
  перевода строки: `1e100.netytimg.com` = `1e100.net` + `ytimg.com`) и разделяют их
  одной кнопкой.

### Changed
- Статусы движков как в макете: «работает / частично / остановлен». Движок, чья
  проба не проходит, теперь «частично», а не зелёный «в порядке»; строка пробы
  красная.
- Инсталлятор больше не показывает токен: в конце — адрес панели, вход по `root`, ссылка
  на контроллер. `AGENT_URL` / `AGENT_TOKEN` у контроллера необязательны,
  `CONTROLLER_TOKEN` больше не используется.

### Fixed
- Аптайм движков всегда был «0с»: init-скрипты считают его через `stat`, которого на
  роутере может не быть. Теперь nuxk-core берёт время старта процесса из `/proc`.
- Шапка на узком экране больше не вылезает за край (заголовок сжимается).

## [0.2.0-beta.1] — 2026-09-25

Агент на роутере и контроллер на Pi, между ними — контракт OpenAPI. Чистая версия
для первого теста на основном роутере. Инструкция — [`docs/BETA.md`](docs/BETA.md).

### Added
- **nuxk-controller** (Pi, :4200): полный веб, час истории графиков, прокси к агенту
  роутера со своим токеном (токен роутера в браузер не попадает), поток событий
  насквозь. `deploy/pi`: образ и сервис в профиле `controller`.
- **Контракт OpenAPI**: `nuxk-core/api/openapi.yaml` описывает ровно то, что отдаёт
  агент; CI сверяет его с маршрутами и полями ответов, типы веба генерируются из него.
- Агент: `GET /info` (роутер или стенд, модель, KeeneticOS), `/metrics` (трафик
  интерфейсов, WAN, пакеты NFQUEUE, conntrack, память — счётчики `/proc`),
  `/logs`, `/events` (SSE: статус и лог).
- **Веб как в согласованном макете**: дашборд (KPI, графики WAN и NFQUEUE, карточки
  движков со спарклайнами, трафик туннелей, «Требует внимания»), страницы движков,
  живой лог, «Система»; интерфейс явно пишет, открыт ли он на роутере или на стенде.
- Инсталлятор: кнопка «Квартира» подставляет SSH-порт 22.

### Changed
- nuxk управляет списком nfqws2 (`user.list`) только после появления первого списка
  «DPI» (`manage_desync`) — свой список пользователя не стирается случайно.
- Лог nuxk-core ротируется самим процессом (2 × 512 КиБ); повторяющаяся ошибка
  движка пишется один раз. `GOMEMLIMIT=48MiB`.
- Адаптер nfqws2 отдаёт в `info` не больше 200 доменов (счётчик точный).

### Fixed
- Вызов init-скрипта больше не зависает навсегда, если запущенный им демон держит
  его stdout.
- Состояние пишется с fsync файла и каталога: пропадание питания не оставляет
  пустой файл списков.
- `/status` не ждёт медленную синхронизацию с прошивкой (до 2 минут).
- Лимит тела запроса 4 МиБ; заголовки `nosniff`, `X-Frame-Options: DENY`,
  `no-referrer`.

## [0.1.0-beta.1] — 2026-09-25

Первая бета: стенд на Raspberry Pi, установка nuxk на роутер Keenetic и
плоскость маршрутизации поверх встроенной маршрутизации KeeneticOS по доменам.
Инструкция — [`docs/BETA.md`](docs/BETA.md).

### Added
- **Плоскость маршрутизации** (`nuxk-core/internal/plane`, бэкенд `keenetic`):
  ведёт встроенную маршрутизацию KeeneticOS по доменам через RCI —
  группы `nuxk-warp` / `nuxk-vless` и их `dns-proxy route`, только объекты
  `nuxk-*`. По умолчанию только план (`PLANE_APPLY=0`). IPv6 к доменам из
  групп отклоняется (`NUXK_V6_DENY`) — прошивка его не маршрутизирует.
  Импорт своих списков роутера без пересечений (домен остаётся «конфликтом»,
  пока он в старом списке). API `/api/v1/plane*`, статус в `/status`.
- **Три списка**: «DPI» (домены уходят в список nfqws2, трафик напрямую),
  «WARP» (группа `nuxk-warp` → OpkgTun0, usque), «VLESS» (`nuxk-vless` →
  OpkgTun1, xray). При настроенном WARP `cloudflareclient.com` всегда в DPI —
  «WARP через nfqws». Общая политика при падении туннеля: напрямую (по
  умолчанию, `auto` в прошивке) или блокировать.
- **Новый интерфейс nuxk-web**: боковое меню, «Обзор», «Списки» (три списка,
  вставка списком, политика туннеля, план и изменения на роутере, конфликты,
  импорт своих списков Keenetic), карточки движков, «Система», тёмная тема,
  мобильная вёрстка. Экраны без данных в ядре (соединения, подбор, решения)
  честно помечены как будущие.
- **WARP на роутере через инсталлятор**: ipk форка `engines/nuxk-usque` под
  mips/mipsel/aarch64 в сборке; шаг по желанию (регистрация в Cloudflare,
  интерфейс OpkgTun, сохранение конфигурации роутера). Перед установкой
  `cloudflareclient.com` добавляется в список nfqws2. Первый запуск переносит
  текущий `user.list` nfqws2 в список «DPI».
- `tools/e0`: проверки роутера (E0, E0c) только на чтение.
- **nuxk-installer** — веб-форма установки на роутер по SSH Entware. Проверяет
  роутер только на чтение (архитектура, Entware, место, часы, модули ядра,
  пакеты, установленный nuxk) и ставит лишь недостающее: `curl`,
  `ca-certificates`, `ipset`; репозиторий и пакет `nfqws2-keenetic`; nuxk-core
  под архитектуру роутера, init-скрипт, веб-панель; `nuxk.conf` (0600, адрес
  только в LAN, новый API-токен); запуск и проверка `/api/v1/healthz`.
  Код доступа к форме, ключ SSH роутера закрепляется после проверки, пароль
  нигде не хранится. Сборки: linux arm64/amd64, Windows, macOS.
- **S51nfqws2-nuxk** — прослойка поверх штатного `nfqws2-keenetic`: запуск и
  остановка идут в штатный скрипт, `info`/`probe`/`apply-*` работают с его
  списками. Пакет остаётся штатным и обновляется через `opkg upgrade`.
- **deploy/pi** — стек беты для Pi: стенд прототипа (:4242) + инсталлятор
  (:4300), скрипт `bootstrap.sh` (проверки, модули ядра, клон, сборка,
  регистрация WARP, запуск). Этапы стенда — в `deploy/pi/.env`.
- nuxk-core: флаг `-version`. nuxk-web: вход по API-токену, если сборка без
  вшитого токена (роутер).

### Changed
- `make check` проверяет и инсталлятор (включая сквозной тест через настоящий
  SSH), `make release` кладёт в бандл сборки инсталлятора.
- Этапы прототипа задаются переменными `NUXK_ENABLE_*` вместо правки compose.
- nfqws2: версия пакета видна в карточке движка.

### Fixed
- Стенд: проба nfqws2 больше не пишет «ok» при таймауте curl.

## [0.1.0-alpha.1] — 2026-09-24

Первая тестовая сборка: стенд `deploy/proto` на Raspberry Pi 5, этапы A–C
(usque → DNS через WARP → nfqws2). xray — только на заглушке.

### Added
- **Контроллер желаемого состояния** (`nuxk-core/internal/core/controller.go`)
  вместо пассивного reconcile-цикла. Намерения пользователя (запуск/остановка,
  маршруты, конфиг xray) хранятся в `state/engines/<kind>.json` (0600) и
  приводятся в жизнь:
  - автоперезапуск движка, который должен работать, с backoff 10с → 5мин;
  - повторное применение маршрутов и конфига, потерянных движком (пересоздан
    контейнер, перепрошит роутер) — при старте ядра;
  - автоматический hardening: IP апстримов usque/xray сами попадают в
    `endpoints.list` nfqws2 вместе с ручными.
- Поля `want_run` и `last_error` в `/status` и `/engines`; в вебе — строка
  «автозапуск» и текст последней ошибки на карточке и в деталях движка.
- Адаптер **xray** (VLESS-Reality), `PUT /api/v1/engines/{kind}/config`,
  вкладка xray с заданием сервера (`vless://` или подписка 3x-ui).
- Адаптер **nfqws2** и редактор списка десинка в вебе.
- Версионирование: `VERSION`, `scripts/version.sh`, `commit` в `/version`,
  версия веба в шапке, `make release` (ядро mips/mipsel/aarch64/x86_64 +
  веб full/lite + SHA256SUMS), CI на GitHub и релиз по тегу `v*`.
- Настройки `INFO_EVERY` / `PROBE_EVERY` (секунды) в `nuxk.conf`.

### Changed
- Движок подключается, только если его скрипт задан в конфиге и существует:
  нет больше вечных карточек «unknown» и предупреждений раз в 5 секунд.
  `ENGINE_X=` (пусто) — явно выключить.
- Опрос движков параллельный, с отдельным таймаутом на каждый (25с), вместо
  одного общего таймаута 20с на все подряд.
- Каждый движок обёрнут блокировкой: скрипт одного движка не запускается
  дважды одновременно (reconcile + кнопка, две вкладки браузера).
- nfqws2 `ApplyRouting`: `nil`-список не трогает соответствующий файл,
  пустой — очищает.
- Прототип: nfqws2 (zapret2) закреплён на `v1.0.5.2` вместо `latest`;
  тома `nuxk-state` и `nfqws2-lists` — состояние и списки переживают
  `up --build`; xray явно выключен.

### Fixed
- Ошибка скрипта движка теперь содержит его собственный вывод, а не только
  `exit status 1`.
- `info`/`probe` разбирают только stdout: предупреждения из stderr больше не
  превращаются в ложные ключи.
- Кнопки в вебе больше не глотают ошибки молча.
- Сравнение API-токена — за постоянное время.
- Скрипты (`S5x*-mock`, `S51*-docker`, `entrypoint.sh`, `S99nuxk-core`)
  закоммичены исполняемыми — `chmod +x` вручную больше не нужен.
- Заглушки usque и xray больше не делят один файл состояния.

### Known limitations
- `nuxk-plane` не подключён: трафик LAN-клиентов в туннели не заворачивается;
  в прототипе — временный `routing-glue.sh` (только DNS через WARP).
- `endpoints.list` nfqws2 пишется, но nfqws2 его пока не читает (ipset —
  следующий этап).
- Настоящего `S52xray` нет, пакетов opkg нет.
- Токен прототипа вшит в JS-сборку — только для изолированного стенда.
