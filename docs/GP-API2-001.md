# Решение GP-API2-001 — интеграция Core API 2
Статус: реализация в Horizon по поручению Александра. Совместный выпуск требует проверки.
Редакция правил: GP-HORIZON-WORKFLOW draft.4.

## 1. Контекст
GP-coordination PR #12, коммит 03e695717fe4fbf8c13777af2f6136fb62c5077d.
Контракт API 2 draft.34 и Core 8748e6c39248ddda5ee8ce7f32d3b5049f2432b8.

## 2. Проблема
Прежний клиент Horizon использует API 1, включая авторизацию, прогоны и каталог.

## 3. Варианты
Плагин на Pi сохраняет существующее управление жизненным циклом и пароль в контроллере.
Самостоятельный Web GP потребовал бы отдельную сессию и отдельную навигацию.

## 4. Решение
Версионированный прокси API 2 и экраны по макету PR #12 внутри Horizon. Состав нового
комплекта и применение на Keenetic требуют отдельной реализации и проверки.

## 5. Действия
Подключить поставку Core, авторизацию, транспорт и интерфейс. Проверять на отдельном
стенде Pi, включая перенос данных и доступ после восстановления.

## 6. Проверка
Вход, смена заводского пароля, запуск обоих движков, SSE, журнал, остановка и
возобновление, каталог и архивы, списки, история, backup/restore.

## 7. Совместимость и откат
Сохранить клиент API 1 для существующих установок. Для отката миграции сохранить
исходное состояние плагина до запуска новой сборки.
