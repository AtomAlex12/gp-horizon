# Решение HZ-0001: метрики кандидатов стратегий GP для системы решений GP Horizon

Статус: предложено (разработчики GP Horizon, 2026-10-20)
Редакция правил: GP-HORIZON-WORKFLOW 1.0-draft.3
Важно: чтение этого файла не разрешает изменений; действия — только по разделу 5
после статуса «согласовано».

## 1. Контекст — что есть сейчас

- GP Horizon строит «систему решений»: для каждого сайта она проверяет пути (напрямую,
  DPI через nfqws2, WARP, VLESS) и **советует** человеку подходящий. Сама она ничего не
  применяет. Выбирается первый «достаточно хороший» путь, а не самый быстрый: сайт должен
  открываться в 4 замерах из 5, первый байт — не дольше 5 с, скорость (если её удалось
  измерить) — не ниже 2 Мбит/с.
- Когда DPI с уже известными стратегиями не помогает, система советует подбор стратегии в
  GP Plane (плагин GP на Raspberry Pi), а на время подбора — WARP.
- Кандидат стратегии в API GP Plane (`StrategyCandidate` в `openapi.json`, версия v0.4.4,
  копия в GP Horizon: `nuxk-controller/plugins/gp/openapi.json`) содержит `id`, `protocol`,
  `args`, `status`, `seen[]{run_id, domain, test, ip_version, seen_at}`, сведения о
  семействе и фрагментации. **Времени, скорости и доли успешных попыток в нём нет**:
  «успех» — только то, что кандидат попал в `seen`.
- По данным zapret2 и dpi-checkers, с июня 2025 ТСПУ «замораживает» соединения с IP
  зарубежных хостингов и CDN: рукопожатие TLS и первые ~16 КБ (около 25 пакетов в обе стороны)
  проходят, дальше соединение молча стоит. Проверка «рукопожатие прошло» или запрос `HEAD`
  такую блокировку не видит. В blockcheck2 по умолчанию HTTPS проверяется запросом `HEAD`
  с `CURL_MAX_TIME=2`; для обнаружения заморозки авторы советуют `CURL_HTTPS_GET=1` с длинным
  ответом или `CURL_PAD`.

## 2. Проблема

Системе решений GP Horizon нужно выбрать из найденных стратегий не первую попавшуюся, а
достаточно хорошую по надёжности и скорости. Без метрик кандидата она может:
- посоветовать стратегию, которая проходит рукопожатие, но сайт «замерзает» после 16 КБ;
- посоветовать стратегию, которая сработала один раз из пяти;
- не отличить быструю стратегию от той, что даёт первый байт через 4 с.

## 3. Варианты

1. **GP Plane добавляет метрики кандидата** — по каждой проверке, в которой кандидат
   участвовал. Плюсы: измерение остаётся там, где запускается движок, без дублирования.
   Метрики нужны и в базовом веб-интерфейсе GP Plane. Минусы: правка API GP Plane и
   совместимость версий. **Выбран.**
2. GP Horizon перепроверяет кандидатов, временно применяя их на роутере. Отвергнут: каждое
   применение перезапускает nfqws2 для всей домашней сети, а это действие на роутере без
   согласия пользователя.
3. GP Horizon сам меряет кандидатов на Pi своим экземпляром nfqws2. Отвергнут: дублирует
   движок GP Plane и пересекает границу его root-helper.

## 4. Решение (предлагается)

В `StrategyCandidate` (или в отдельном объекте `quality`, на усмотрение GP Plane) появляются
необязательные поля по каждому домену и тесту:

| Поле | Смысл |
|---|---|
| `tries` | сколько раз кандидат проверялся |
| `ok` | сколько из них успешно |
| `connect_ms`, `tls_ms`, `ttfb_ms` | медианы: TCP, TLS, первый байт ответа |
| `bytes` | сколько байт ответа получено (проверка ≥ 64 КБ против заморозки) |
| `kbps` | медиана скорости, если ответ ≥ 128 КБ; иначе отсутствует |
| `frozen` | соединение встало после первых ~16 КБ |
| `measured_at` | когда измерено |

Что остаётся как было: формат `args`, порядок составных стратегий, `seen[]`, авторизация и
владение данными GP Plane. GP Horizon только читает эти поля и ничего не пишет.

## 5. Действия (после статуса «согласовано»)

- **GP Plane:** добавить поля в API и в проверку blockcheck2 (GET с длинным ответом, не
  только HEAD), выпустить версию, указать в описании релиза, с какой версии поля есть.
- **GP Horizon:** заменить копию `openapi.json` контрактом новой версии, `npm run gen:gp`,
  использовать метрики в рекомендациях («лучший кандидат по надёжности, затем по первому
  байту»), закрепить версию плагина (`default_version`).
- Права: обычные для каждого репозитория; устройства пользователей не затрагиваются.

## 6. Проверка

- В ответе `GET /api/core/strategy-candidates` у кандидатов, найденных новой версией, есть
  `tries`, `ok`, `ttfb_ms`.
- Кандидат, которому мешает заморозка, получает `frozen=true` на тестовом сайте за
  иностранным CDN.
- GP Horizon на старой версии GP Plane (без полей) работает как раньше.

## 7. Совместимость и откат

Поля необязательные: старый GP Horizon их не читает, новый GP Horizon без них советует как
сейчас — первую найденную стратегию с пометкой «скорость не измерена». Откат GP Plane на
версию без полей ничего не ломает.
