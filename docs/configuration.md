Большинство настроек меняется в панели: списки, серверы VLESS, защищённый DNS, проверка
обновлений, плагины. Вручную редактируется только `nuxk.conf` на роутере — в основном чтобы
включить применение маршрутизации (`PLANE_APPLY`).

---

## Роутер: `nuxk.conf`

Путь — `/opt/etc/nuxk/nuxk.conf`, права `0600`. Формат совместим с shell: `КЛЮЧ="значение"`,
строки с `#` — комментарии. Установщик создаёт файл один раз; `nuxk update` его не
перезаписывает. После правки перезапустите агент:

```sh
/opt/etc/init.d/S99nuxk-core restart
```

В таблице: **по умолчанию** — значение агента, если ключа нет в файле; **установщик** —
значение, которое записывает `nuxk-lite.sh`.

### API и вход

| Ключ | По умолчанию | Установщик | Назначение |
|---|---|---|---|
| `LISTEN` | `127.0.0.1:4141` | `<адрес-LAN>:4141` | Адрес API и веб-интерфейса. Установщик выбирает адрес роутера в домашней сети — агент не слушает WAN. |
| `API_TOKEN` | пусто | 128 случайных бит | Токен для программ (контроллера на Pi). Контроллер получает его сам при подключении по паролю root; копировать его вручную не нужно. |
| `AUTH_USER` | `root` | — | Учётная запись для входа в веб-интерфейс. `off` — вход в браузере отключён. |
| `AUTH_FILES` | `/opt/etc/shadow /opt/etc/passwd` | — | Где проверяется пароль (по порядку). Поддерживаются хеши `$1$`, `$5$`, `$6$`. |
| `WEB_ROOT` | пусто | `/opt/share/www/nuxk` | Каталог лёгкого веб-интерфейса. Пусто — только API. |
| `NODE_ROLE` | определяется | — | `router`, `stand` или `host`. По умолчанию — `router`, если на узле есть `ndmc`. Используется для подписи узла в интерфейсе. |

### Состояние и опрос движков

| Ключ | По умолчанию | Установщик | Назначение |
|---|---|---|---|
| `STATE_DIR` | `/opt/etc/nuxk` | `/opt/etc/nuxk` | Каталог состояния: списки, желаемые состояния движков, настройки. |
| `INFO_EVERY` | `5` | `10` | Период опроса состояния движков, секунды. Каждый опрос запускает по одному процессу на движок. |
| `PROBE_EVERY` | `60` | `120` | Период активной пробы движков (открытие сайтов, проверка туннелей), секунды. |

### Движки

| Ключ | По умолчанию | Установщик | Назначение |
|---|---|---|---|
| `ENGINE_NFQWS2` | `/opt/etc/init.d/S51nfqws2` | `/opt/etc/nuxk/engines/S51nfqws2-nuxk` или пусто | Скрипт, через который агент управляет nfqws2. Установщик указывает адаптер nuxk поверх штатного пакета. |
| `ENGINE_USQUE` | `/opt/etc/init.d/S51usque` | путь или пусто | WARP (usque). |
| `ENGINE_XRAY` | `/opt/etc/init.d/S52xray-nuxk` | путь или пусто | VLESS (xray). |

Пустое значение — движок выключен. Путь к несуществующему файлу — движок не установлен и
не подключается.

### Маршрутизация по спискам

| Ключ | По умолчанию | Установщик | Назначение |
|---|---|---|---|
| `PLANE` | выключено | `keenetic` | Бэкенд маршрутизации: `keenetic` — встроенная маршрутизация KeeneticOS по доменам через RCI. Пусто или `off` — выключено. |
| `PLANE_APPLY` | `0` | `0` | `1` — применять изменения на роутере. `0` — **режим плана**: панель показывает, что было бы сделано, роутер не изменяется. |
| `PLANE_RCI` | `http://127.0.0.1:79` | — | Адрес RCI KeeneticOS. С самого роутера RCI доступен без пароля. |
| `PLANE_V6` | `deny` | `deny` | `deny` — отклонять IPv6 к доменам списков WARP/VLESS (цепочка `NUXK_V6_DENY`), чтобы клиенты перешли на IPv4, который маршрутизируется. `off` — не трогать IPv6. |
| `PLANE_IFACE_WARP` | `OpkgTun0` | интерфейс usque | Интерфейс Keenetic для списков WARP. |
| `PLANE_IFACE_VLESS` | `OpkgTun1` | интерфейс xray | Интерфейс Keenetic для списков VLESS. |
| `PLANE_EVERY` | `60` | — | Период сверки желаемого состояния с роутером, секунды. После сохранения списков сверка выполняется сразу. |

Маршрутизация затрагивает только объекты `nuxk-*` (группы `nuxk-warp`, `nuxk-vless` и их
маршруты), не сохраняет их в конфигурацию роутера и поддерживает KeeneticOS 4.x и 5.x — с
другими версиями изменения не выполняются. Список DPI передаётся в `user.list` nfqws2.

### Обновления из панели

| Ключ | По умолчанию | Назначение |
|---|---|---|
| `UPDATE_REPO` | `AtomAlex12/gp-horizon` | Репозиторий релизов. |
| `UPDATE_API` | `https://api.github.com` | API GitHub или его зеркало. |
| `UPDATE_COMMAND` | `/opt/bin/nuxk` | Команда, которой агент выполняет обновление и установку компонентов. Пусто — обновление из панели недоступно, остаётся только уведомление о новой версии. |
| `UPDATE_BASE_URL` | GitHub | Зеркало файлов релизов. |

Проверку раз в сутки и канал (только релизы или с бетами) включают в панели: «Система» →
«Обновления».

### Защищённый DNS

| Ключ | По умолчанию | Назначение |
|---|---|---|
| `DNS_LISTEN` | `<адрес-LAN>:53053` | Адрес DNS-форвардера nuxk. Петлевой адрес KeeneticOS не принимает, поэтому по умолчанию используется адрес из `LISTEN`. |
| `DNS_ROUTER` | `<адрес-LAN>:53` | DNS-прокси роутера — для самопроверки после включения. |
| `SMARTDNS_INIT` | `/opt/etc/init.d/S53smartdns-nuxk` | Init-скрипт SmartDNS. `off` — не предлагать SmartDNS. |
| `SMARTDNS_DIR` | `/tmp/smartdns-nuxk` | Каталог в ОЗУ для журналов SmartDNS. |

Включение, выбор серверов DoH и пути (VLESS, WARP, напрямую) выполняются в панели: «DNS».

Самопроверка: через туннель DNS идёт, только пока туннель подключён, иначе — напрямую по DoH.
Раз в 30 с агент спрашивает имя, которого нет в кэше; ответ с ошибкой или дольше 1,5 с — отказ.
Две неудачи подряд — SmartDNS перезапускается (не чаще раза в 5 мин), три — DNS отдаётся самому
Keenetic до тех пор, пока nuxk снова не начнёт отвечать быстро. Все эти события пишутся в журнал.

### Пример

Файл, который пишет установщик на роутере с WARP и VLESS (токен и адрес заменены):

```sh
LISTEN="192.168.1.1:4141"
API_TOKEN="<32 шестнадцатеричных символа>"
STATE_DIR="/opt/etc/nuxk"
WEB_ROOT="/opt/share/www/nuxk"
ENGINE_NFQWS2="/opt/etc/nuxk/engines/S51nfqws2-nuxk"
ENGINE_USQUE="/opt/etc/init.d/S51usque"
ENGINE_XRAY="/opt/etc/init.d/S52xray-nuxk"
INFO_EVERY="10"
PROBE_EVERY="120"
PLANE="keenetic"
PLANE_APPLY="0"
PLANE_V6="deny"
PLANE_IFACE_WARP="OpkgTun0"
PLANE_IFACE_VLESS="OpkgTun1"
```

## Роутер: файлы и каталоги

| Путь | Назначение |
|---|---|
| `/opt/usr/bin/nuxk-core` | Агент. |
| `/opt/bin/nuxk` | Команда `nuxk` (копия `nuxk-lite.sh`). |
| `/opt/etc/init.d/S99nuxk-core` | Init-скрипт агента. |
| `/opt/etc/nuxk/nuxk.conf` | Конфигурация агента (`0600`). |
| `/opt/etc/nuxk/` | Состояние: списки (`plane.json`), желаемые состояния движков, настройки DNS и обновлений, конфигурация xray (`0600`). |
| `/opt/etc/nuxk/engines/S51nfqws2-nuxk` | Адаптер nfqws2. |
| `/opt/share/www/nuxk/` | Лёгкий веб-интерфейс. |
| `/opt/var/log/nuxk-core.log`, `.log.1` | Журнал агента, не более 2 × 512 КиБ. |
| `/opt/var/log/nuxk-core.crash` | Аварийный вывод агента (stderr); при запуске обрезается, если превышает 64 КиБ. |
| `/opt/var/lib/nuxk/prev/` | Предыдущая версия для `nuxk rollback`. |
| `/opt/etc/nuxk.removed/` | Конфигурация и списки после `nuxk uninstall`. |
| `/opt/etc/nfqws2/lists/user.list` | Список доменов nfqws2; при наличии списка DPI им управляет nuxk. |
| `/opt/sbin/xray`, `/opt/etc/init.d/S52xray-nuxk`, `/opt/etc/xray/` | xray и его init-скрипт (после `nuxk vless`). |
| `/opt/sbin/smartdns`, `/opt/etc/init.d/S53smartdns-nuxk`, `/opt/etc/smartdns-nuxk/` | SmartDNS (после `nuxk dns`). |

## Контроллер: переменные окружения

Задаются в `~/nuxk/docker-compose.yml`. Установщик пишет только необходимое; остальное — на
случай особых установок.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `LISTEN` | `:4200` | Адрес веб-интерфейса и API в контейнере. Порт на Pi задаётся `NUXK_PORT` установщика. |
| `WEB_ROOT` | `/usr/share/nuxk-web` (в образе) | Каталог полной версии веб-интерфейса. |
| `DATA_DIR` | `/var/lib/nuxk-controller` | Данные: хеш пароля администратора, подключение к роутеру, серверы VLESS, плагины. |
| `UPDATE_DIR` | `/var/lib/nuxk-update` | Каталог запросов на обновление (`~/nuxk/update` на Pi). |
| `AGENT_URL`, `AGENT_TOKEN` | — | Подключить роутер без мастера настройки — используется, только если подключение ещё не сохранено. |
| `PLUGIN_RECIPES` | `/usr/share/nuxk/plugins` | Рецепты плагинов (режим `supervise`). |
| `SUPERVISOR_SOCK` | `/run/nuxk/supervisor.sock` | Сокет хоста плагинов; `supervise` задаёт его процессу `serve` сам. |

## Контроллер: файлы и тома

| Путь | Назначение |
|---|---|
| том `controller-data` → `/var/lib/nuxk-controller` | Данные контроллера. Удаляется только `nuxk-pi uninstall --purge`. |
| `…/plugins/<имя>/` | Плагин: версии (`versions/`), данные (`data/`), временный каталог (`tmp/`), журналы установки и работы (`install.log`, `run.log`). |
| `~/nuxk/update/` | Запросы панели на обновление и журнал обновления (`update.log`). |

## Сетевые порты

| Порт | Где | Назначение |
|---|---|---|
| `4141/tcp` | роутер, адрес LAN | API и лёгкий веб-интерфейс агента. |
| `53053/udp, tcp` | роутер, адрес LAN | DNS-форвардер nuxk (если защищённый DNS включён). |
| `79/tcp` | роутер, `127.0.0.1` | RCI KeeneticOS — используется агентом локально. |
| `4200/tcp` | Pi | Полный веб-интерфейс и API контроллера. |
| `8081/tcp` | Pi, внутри контейнера, `127.0.0.1` | API ядра GP; снаружи недоступен, к нему обращается только контроллер. |
