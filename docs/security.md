# Модель безопасности

GP Horizon работает на основном роутере дома или офиса, поэтому проект исходит из двух
требований: **не нарушить работу роутера** и **не допустить подмены устанавливаемого кода**.

## Изменения на роутере

- **Режим плана по умолчанию.** Свежая установка не меняет маршрутизацию роутера
  (`PLANE_APPLY="0"`): панель показывает план — какие объекты были бы созданы. Применение
  включается вручную в `nuxk.conf`.
- **Только свои объекты.** Маршрутизация создаёт и удаляет только объекты с префиксом
  `nuxk-` (группы `nuxk-warp`, `nuxk-vless` и их маршруты, цепочка `NUXK_V6_DENY`);
  запрос на изменение любого другого объекта отклоняется на уровне агента. Собственные
  списки и маршруты пользователя не изменяются: домены, уже стоящие в них, показываются как
  конфликты.
- **Без сохранения конфигурации.** Объекты маршрутизации nuxk не записываются в
  `startup-config`: после перезагрузки их восстанавливает агент, а без агента их нет.
- **Явное согласие на изменение конфигурации.** Установка WARP и VLESS создаёт интерфейс
  OpkgTun и сохраняет конфигурацию роутера — только после ответа «да» в установщике. Чужие
  интерфейсы не используются: для VLESS берётся первый свободный OpkgTun с описанием
  `nuxk-vless`.
- **Проверенные версии прошивки.** Маршрутизация работает с KeeneticOS 4.x и 5.x; на другой
  версии агент отказывается вносить изменения.
- **Откат.** Удаление списков в панели убирает объекты `nuxk-*`; `PLANE_APPLY="0"`
  прекращает изменения; `nuxk uninstall` удаляет nuxk полностью, оставляя конфигурацию и
  списки в `/opt/etc/nuxk.removed`.

## Цепочка поставки

- **Ничего не собирается на устройствах.** Установщики скачивают готовые файлы релиза.
- **Хеши.** Каждый файл сверяется с `SHA256SUMS` релиза до записи на устройство.
- **Подпись.** `SHA256SUMS` подписывается ключом Ed25519 при сборке релиза в GitHub Actions
  (закрытый ключ хранится только в секрете репозитория). На роутере подпись проверяет уже
  установленный агент (`nuxk-core -verify`) — подменённый или неподписанный релиз не будет
  установлен, в том числе при обновлении кнопкой. Установщик Pi проверяет подпись через
  `ssh-keygen -Y verify`.
  Отпечаток ключа: `SHA256:T2omf5hHIbtKjT4l5WOoKb4dj2syNWjHDDy+5j1xSr4`.
- **Сторонние программы — по закреплённым хешам.** xray-core (релизы XTLS) и SmartDNS
  (релизы pymumu) скачиваются у авторов и проверяются по хешам, записанным в установщике.
  nfqws2-keenetic ставится из репозитория пакета через `opkg`.
- **Образ контроллера — по отпечатку.** Релиз содержит точный отпечаток (digest) образа
  `ghcr.io/atomalex12/nuxk-horizon-controller`; установщик запускает образ именно по нему.
- **Без понижения версии.** Обновление без явного `NUXK_VERSION` не устанавливает версию
  старее текущей.
- **Автоматический откат.** Если после обновления агент не ответил за 15 с (роутер) или
  контроллер — за 60 с (Pi), возвращается прежняя версия.

Ручная проверка релиза (OpenSSH 8.1+, файл `allowed_signers` — в
[`nuxk-core/internal/release/`](../nuxk-core/internal/release/)):

```sh
ssh-keygen -Y verify -f allowed_signers -I release@nuxk-horizon -n nuxk-release -s SHA256SUMS.sig < SHA256SUMS
sha256sum -c SHA256SUMS
```

## Доступ к агенту

- **Только локальная сеть.** Установщик настраивает агент на адрес роутера в домашней сети
  (`LISTEN`), а не на все интерфейсы.
- **Вход учётной записью роутера.** Человек входит как `root` с паролем Entware; пароль
  проверяется по `/opt/etc/shadow` и нигде не сохраняется агентом.
- **Защита от подбора.** После 5 неудачных попыток подряд вход с адреса блокируется на
  30 с, далее срок удваивается до 15 мин.
- **Сессии** хранятся в памяти (не более 32), истекают через 12 ч без обращений.
- **Токен для программ** (`API_TOKEN`, 128 случайных бит) хранится в `nuxk.conf` с правами
  `0600`. Контроллер получает его один раз по паролю root (`/auth/pair`); пароль при этом не
  сохраняется.
- **Секреты движков не отдаются.** Конфигурация xray хранится с правами `0600`; API
  показывает только адрес сервера и параметры без ключей.

## Контроллер на Pi

- **Пароль администратора** хранится как PBKDF2-SHA256 (600 000 итераций, соль).
- **Сессии** истекают через 12 ч без обращений; вход защищён от подбора так же, как у агента.
- **Защита от межсайтовых запросов.** Изменяющие запросы принимаются только со страницы
  самого контроллера (проверка `Origin`).
- **Токен роутера не попадает в браузер:** прокси к агенту подставляет его на стороне
  контроллера.
- **Контейнер с минимальными правами:** корневая файловая система только для чтения, все
  привилегии сброшены кроме перечисленных в `docker-compose.yml`, `no-new-privileges`.
  Веб-интерфейс и API работают от пользователя `nobody` без привилегий.
- **Обновление без доступа к Docker.** Контроллер оставляет запрос в каталоге, а обновление
  выполняет служба systemd на Pi (`nuxk-update.path`).

## Плагины

- Плагин работает в том же контейнере отдельным процессом: uid 0, но только с правами из
  своего `plugin.json` (разрешённый набор — `allowedCaps` в `plugin.go`; без `CAP_DAC_*` и
  `SYS_PTRACE`) и без возможности их расширить.
- Окружение плагина формируется заново: токены и настройки контроллера в него не передаются.
- Код плагина скачивается из его релизов с проверкой хешей; у каждого плагина свой каталог
  данных и временный каталог.
- API ядра GP слушает только `127.0.0.1` внутри контейнера. Контроллер пропускает к нему
  лишь перечисленные вызовы (`gpAllowed`) — без авторизации GP и установочных хранилищ —
  и при первом подключении заменяет заводской пароль GP случайным.

## Журналы и секреты

- Агент пишет на флеш роутера только записи уровня info и выше, файл ограничен 2 × 512 КиБ.
- Отладочный журнал хранится только в памяти и выключается сам (до 4 ч).
- В журналы не попадают: stdin скриптов движков (конфигурации с ключами), ответы RCI на
  чтение (конфигурация роутера), пути и параметры ссылок подписок, токены, пароли.
- Не публикуйте `nuxk.conf` целиком (в нём `API_TOKEN`) и вывод `show running-config`
  Keenetic.
