Трёхслойный обход: nfqws2, WARP-MASQUE и VLESS под одной панелью

К августу 2026 ни один метод по отдельности не держит весь список. Плана два: решить, какой трафик каким слоем идёт, и собрать три движка и один веб-интерфейс так, чтобы они не мешали друг другу на роутере.

01 Сеть сейчас

Блокировка сместилась с «по протоколу» на «по поведению», и добавился слой замедления на стыках внутри страны.

Кратко то, что определяет выбор архитектуры (по открытым сводкам, лето–август 2026 — детали зависят от провайдера и региона):

Волна по VLESS / SOCKS5 / L2TP

С начала августа РКН массово рвёт ранее рабочие протоколы прокси. VLESS без доработок ловится. авг 2026

ТСПУ по fingerprint

Соединения режутся по поведению и метаданным потока, а не по сигнатуре протокола. Reality-маскировка перестаёт быть достаточной сама по себе. июнь 2026

ТСПУ на внутренних стыках

Оборудование ставят на узлах между сетями внутри РФ — замедляется весь транзитный трафик, не только «подозрительный». авг 2026

Cloudflare по IP

Подсети CF в реестре с июня 2025. WARP-over-WireGuard (UDP) провайдеры подрезают; MASQUE (HTTP/3 на 443) живёт, т.к. неотличим от HTTPS. 2025–2026

zapret 1.9.3

Экстренный патч под изменения ТСПУ: динамическая фрагментация, лучше QUIC/HTTP-3. Стратегия — своя под каждого провайдера. июнь 2026

Часть доменов мертва

Есть ресурсы, которые не открываются ни десинком, ни через WARP (IP-null-route + гео-замок на стороне сервиса). Остаётся только чистый зарубежный выход.

Ссылки — в конце документа.

02 Почему именно три слоя

У каждого движка свой класс задач и своя точка отказа. Комбинация закрывает дыры поодиночке.

СлойКогда применяетсяМеханизмТочка отказаЦена
direct Ресурс не тронут обычный маршрут — 0
nfqws2 Блок по SNI / хендшейку, но реальный IP доступен; замедление YouTube/Discord NFQUEUE, desync
fake · split · disorder		 IP-блок; поведенческий ТСПУ; null-route 0 — без туннеля, без задержки
usque Нужен другой egress-IP, а MASQUE у провайдера ещё не режется MASQUE h3:443
→ Cloudflare		 IP CF в реестре; WARP «мягко» блокируют; egress CF сам под гео-замком части сервисов 0 — но выход не «чистый резидентный»
vless Домен мёртв по всем остальным; нужен чистый зарубежный выход VLESS-Reality
xray/sing-box → VPS		 Reality под поведенческим давлением (авг 2026); нужен свой VPS $ — аренда VPS, ручной подбор under-pressure

Порядок предпочтения по стоимости и заметности: сначала десинк (бесплатно, без хопа), потом WARP для середины, VLESS в последнюю очередь — для того, что иначе не достаётся. Каждому слою — свой список доменов; пересечения решаются приоритетом (vless > warp > desync).

05 Единый веб-интерфейс

Наш usque-keenetic-web расширяется с одного движка до трёх — модель уже подходящая.

Что переиспользуется как есть и что добавляется:

  • Тонкий PHP-слой остаётся: парсит cmd, дёргает S51*-скрипты движков, отдаёт JSON. Ничего своего не считает.
  • Общий контракт статуса: каждый движок отдаёт info плоскими key value — панель собирает три карточки одинакового формата (up/down, здоровье, счётчики).
  • Вкладки движков: nfqws2 usque vless — у каждой свой редактор списка + свои пресеты.
  • Общий редактор списков (как у nfqws-keenetic-web): файлы desync/warp/vless/exclude.list, вкладками, с проверкой синтаксиса.
  • Пресеты по сервисам из itdoginfo/allow-domains — назначаются на любой из трёх слоёв.
  • Одна кнопка «Применить»: пишет списки → триггерит плоскость решений (ре-резолв, пере-разметка ipset, маршруты) → показывает «N доменов → M префиксов» по каждому слою.
  • Здоровье по каждому слою: nfqws2 — активна ли стратегия; usque — probe через opkgtun0 (egress IP, PoP, RTT); vless — probe через tun-xray + пинг до VPS.
  • Порт :91, авторизация по юзеру Entware, session_name('bypass_web') — чтобы не пересекаться с nfqws-keenetic-web на :90.
# контракт API — тот же cmd-стиль, +ось движка
POST /api/index.php
  cmd=status                 → {engines:{nfqws2,usque,vless}, plane:{…}}
  cmd=engine&e=usque&op=info|probe|start|stop|restart
  cmd=list_get&e=vless       cmd=list_set&e=vless&content=…
  cmd=preset_toggle&e=warp&preset=youtube
  cmd=apply                  → пере-собрать плоскость по всем спискам

06 Строить или взять готовое

Оркестрация трёх движков под одной панелью уже существует — вопрос в том, чего в ней не хватает.

ПроектЧто делаетЧего не хватает под нашу задачу
spatiumstas/
web4static		 PHP+lighttpd на :99, управляет NFQWS, NFQWS2, XKeen, HydraRoute, Xray, sing-box, mihomo, dnsmasq и др. — ровно идея «один UI на все движки». Нет usque/MASQUE как движка. UX «редактор конфигов», а не «дашборд состояния». Широкий, не сфокусированный.
Ground-Zerro/
HydraRoute (Neo)		 Готовая плоскость решений: перехват DNS → ipset → fwmark → увод в любой туннель/интерфейс по доменам и CIDR. Обкатана на Keenetic, умеет сосуществовать с PBR. Это движок маршрутизации, не панель. Целится в один туннель за раз — многослойность (desync + warp + vless одновременно) надо разложить.
podkop sing-box + nftables, selective routing, ест vless:// напрямую. Своя плоскость. OpenWrt-центричный; на Keenetic — через костыли. Не оркеструет nfqws2.
xkeen Xray/VLESS-Reality на Keenetic + автозапуск. Де-факто стандарт для слоя vless. Только слой vless. Свой роутинг — не общий с остальными.
Рекомендация

Не переписывать оркестрацию с нуля. Реальный вклад — там, где сейчас дыра:

  1. usque/MASQUE как первоклассный движок в этой экосистеме (пакет + S51usque с info/probe — уже сделано в нашей ветке).
  2. HydraRoute как плоскость решений, настроенная на три цели сразу: desync.list → пометка «только nfqws2», warp.list → opkgtun0, vless.list → tun-xray.
  3. Наш дашборд поверх — состояние + пресеты + одна «Применить», три вкладки. Либо отдельным пакетом, либо PR в web4static с добавлением usque.

07 Дорожная карта

Ф.0
Ядро usque + панель (готово в ветке feature/web-ui) Логи, --on-connect-состояние, info/probe/reregister, дашборд, OpenAPI.
Ф.1
Плоскость решений на HydraRoute Развернуть HydraRoute, три списка → три цели (desync-метка, opkgtun0, tun-xray). Проверить на живом роутере: fwmark, номера таблиц, netfilter.d-хук, сосуществование с nfqws2 и Keenetic PBR.
Ф.2
Панель → три движка Общий info-контракт для nfqws2 и xray-обёрток, три вкладки, общий редактор списков, пресеты itdoginfo, кнопка «Применить» дёргает HydraRoute.
Ф.3
Слой vless Обёртка над xkeen/xray: S51-скрипт с info/probe, ввод vless:// в UI, генерация конфига, tun-xray как цель HydraRoute.
Ф.4
Автоматизация Cron: обновление пресетов, ре-резолв, watchdog по probe (авто-рестарт слоя при провале), авто-фолбэк warp → vless для домена, если warp-проба не проходит.

08 Решения за тобой

  • Плоскость решений: HydraRoute (рекоменд., обкатан на Keenetic) / podkop / своя на nftables.
  • Ядро vless: xray (xkeen) / sing-box / mihomo. От этого зависит формат конфига и обёртка.
  • Панель: отдельный пакет bypass-web / PR в web4static с движком usque / развивать наш usque-keenetic-web до трёх вкладок.
  • Форк nfqws2: не нужен — интегрируемся рядом, читаем его S51nfqws2 status и правим его списки в /opt/etc/nfqws2/lists/.
  • Репозиторий: один репо с core + web + плоскостью, или три.
  • VPS для vless: свой (контроль, но обслуживание) / арендный конфиг.
