# Трёхслойный обход: nfqws2 + usque + VLESS под одной панелью

> Визуальная версия с диаграммами: [`plan-3-engine.html`](plan-3-engine.html)
> (открыть в браузере; для коллег — самодостаточный файл).
> Факты по состоянию на конец августа 2026, зависят от провайдера/региона.

## 1. Ситуация в сети

- **Волна по VLESS / SOCKS5 / L2TP** — с начала августа 2026 РКН массово рвёт ранее
  рабочие протоколы прокси. VLESS без доработок ловится.
- **ТСПУ по fingerprint** (июнь 2026) — режут по поведению и метаданным потока, а не по
  сигнатуре. Reality-маскировка перестаёт быть достаточной сама по себе.
- **ТСПУ на внутренних стыках** — замедляется весь транзитный трафик, не только «подозрительный».
- **Cloudflare по IP** — подсети в реестре с июня 2025. WARP-over-WireGuard (UDP) режут;
  MASQUE (HTTP/3 на 443) живёт, т.к. неотличим от HTTPS.
- **zapret 1.9.3** (июнь 2026) — динамическая фрагментация, лучше QUIC/HTTP-3; стратегия
  своя под каждого провайдера.
- **Часть доменов мертва** по всем методам сразу (IP-null-route + гео-замок на стороне
  сервиса) → нужен чистый зарубежный выход.

Вывод: **ни один инструмент в одиночку не тянет весь список** — отсюда слои.

## 2. Три слоя, приоритет `vless > warp > desync`

| Слой | Когда | Механизм | Точка отказа | Цена |
|---|---|---|---|---|
| `direct` | ресурс не тронут | обычный маршрут | — | 0 |
| `nfqws2` | блок по SNI/хендшейку, реальный IP доступен; замедление YT/Discord | NFQUEUE desync (fake/split/disorder) | IP-блок, поведенческий ТСПУ, null-route | 0, без хопа |
| `usque` | нужен другой egress-IP, MASQUE ещё не режут | MASQUE h3:443 → Cloudflare | IP CF в реестре, WARP «мягко» блокируют, гео-замок части сервисов на выходе CF | 0, выход не «резидентный» |
| `vless` | домен мёртв по остальному; нужен чистый зарубежный выход | VLESS-Reality, xray/sing-box → свой VPS | Reality под поведенческим давлением; нужен VPS | $, ручной подбор |

Каждому слою — свой список доменов; пересечения решаются приоритетом.

## 3. Архитектура

```
Клиент LAN
  → DNS-перехват (dnsmasq / HydraRoute): резолв → сверка со списками → ipset
     ├─ нет в списках      → table main (прямой)
     ├─ desync.list        → table main + nfqws2 (NFQUEUE на 80/443/QUIC)
     ├─ warp.list  → fwmark → table 100 → opkgtun0 (usque MASQUE)
     └─ vless.list → fwmark → table 101 → tun-xray (VLESS-Reality)
  → WAN → провайдер → ТСПУ
```

- Плоскость решений **одна на все три движка**; движки о ней не знают, только читают списки.
- **nfqws2 работает пассивно на прямом маршруте** — правит пакеты на выходе, трафик никуда
  не уводит.
- **usque и xray — увод в отдельный интерфейс** через `fwmark` + своя таблица.

### Правила сосуществования (fwmark)

| Потребитель | fwmark | таблица | заметка |
|---|---|---|---|
| Keenetic PBR («Приоритеты подключений») | низкие 28 бит, маска `0x0fffffff` | 42, 43, … | динамический, из `ndmc show ip policy`; занимать нельзя |
| nfqws2 (zapret2) | `0x20000000`, `0x40000000` | — | маскированные, биты 29–30; не маршрутизирует; есть `POLICY_EXCLUDE` |
| наш увод → usque | бит 28 + селектор (своя nft-таблица) | 100 | свободен только бит 28 → два движка развести через 2 ipset + 2 `ip rule`, либо готовой плоскостью |
| наш увод → vless | то же, второй селектор | 101 | пере-применять из `/opt/etc/ndm/netfilter.d/` — Keenetic перестраивает firewall и стирает чужое |

- DNS не подменяем принудительно — перехват рядом с резолвером Keenetic (как HydraRoute)
  или через `dnsmasq` из Entware.
- MASQUE-эндпоинт Cloudflare (`162.159.198.0/24`) нигде не режем — nfqws2 на этом потоке
  помогает хендшейку.

## 4. Единый веб-интерфейс

`usque-keenetic-web` расширяется с одного движка до трёх:

- **Тонкий PHP-слой** остаётся: парсит `cmd`, дёргает `S51*`-скрипты движков, отдаёт JSON.
- **Общий контракт статуса**: каждый движок отдаёт `info` плоскими `key value`.
- **Вкладки движков** `nfqws2 / usque / vless` — у каждой свой редактор списка + пресеты.
- **Общий редактор списков** (как у nfqws-keenetic-web): `desync/warp/vless/exclude.list`.
- **Пресеты по сервисам** из `github.com/itdoginfo/allow-domains` — на любой из трёх слоёв.
- **Одна кнопка «Применить»** → пишет списки → триггерит плоскость решений → «N доменов → M префиксов» по слою.
- **Здоровье по слою**: nfqws2 — активна ли стратегия; usque/vless — `probe` через интерфейс.
- Порт `:91`, `session_name('bypass_web')` — не пересекаться с nfqws-keenetic-web на `:90`.

```
POST /api/index.php
  cmd=status                       → {engines:{nfqws2,usque,vless}, plane:{…}}
  cmd=engine&e=usque&op=info|probe|start|stop|restart
  cmd=list_get&e=vless             cmd=list_set&e=vless&content=…
  cmd=preset_toggle&e=warp&preset=youtube
  cmd=apply                        → пере-собрать плоскость по всем спискам
```

## 5. Строить или взять готовое

| Проект | Что делает | Чего не хватает |
|---|---|---|
| `spatiumstas/web4static` | PHP+lighttpd на `:99`, управляет NFQWS/NFQWS2/XKeen/HydraRoute/Xray/sing-box/mihomo/dnsmasq — **ровно «один UI на все движки»** | нет usque/MASQUE как движка; UX «редактор конфигов», не дашборд |
| `Ground-Zerro/HydraRoute` (Neo) | готовая **плоскость решений**: DNS → ipset → fwmark → увод в любой туннель по доменам/CIDR; обкатана на Keenetic, уживается с PBR | это движок роутинга, не панель; целится в один туннель за раз |
| `podkop` | sing-box + nftables, ест `vless://` напрямую, своя плоскость | OpenWrt-центричный; не оркеструет nfqws2 |
| `xkeen` | Xray/VLESS-Reality на Keenetic, де-факто стандарт слоя vless | только vless; свой роутинг |

**Рекомендация — не переписывать оркестрацию с нуля:**

1. **usque/MASQUE как первоклассный движок** (пакет + `S51usque` с `info`/`probe` — уже
   сделано в ветке `feature/web-ui`).
2. **HydraRoute как плоскость решений** на три цели сразу: `desync.list` → метка «только
   nfqws2», `warp.list` → `opkgtun0`, `vless.list` → `tun-xray`.
3. **Наш дашборд поверх** — состояние + пресеты + одна «Применить», три вкладки. Либо
   отдельным пакетом, либо PR в web4static с добавлением usque.

## 6. Дорожная карта

- **Ф.0 (готово)** — ядро usque + панель: логи, `--on-connect`-состояние, `info`/`probe`/`reregister`, дашборд, OpenAPI.
- **Ф.1** — плоскость решений на HydraRoute: три списка → три цели. Проверить на живом
  роутере: fwmark, номера таблиц, `netfilter.d`-хук, сосуществование с nfqws2 и Keenetic PBR.
- **Ф.2** — панель → три движка: общий `info`-контракт, три вкладки, общий редактор списков,
  пресеты, «Применить» дёргает HydraRoute.
- **Ф.3** — слой vless: обёртка над xkeen/xray (`S51`-скрипт с `info`/`probe`), ввод
  `vless://` в UI, генерация конфига, `tun-xray` как цель HydraRoute.
- **Ф.4** — автоматизация: cron обновления пресетов, ре-резолв, watchdog по `probe`
  (авто-рестарт слоя), авто-фолбэк warp → vless для домена.

## 7. Решения, которые нужно принять

| | варианты |
|---|---|
| Плоскость решений | **HydraRoute** (реком.) / podkop / своя на nftables |
| Ядро vless | xray (xkeen) / sing-box / mihomo — от этого зависит формат конфига и обёртка |
| Панель | отдельный пакет `bypass-web` / PR в web4static с движком usque / растить `usque-keenetic-web` до 3 вкладок |
| Форк nfqws2 | не нужен — интегрируемся рядом, читаем `S51nfqws2 status`, правим `/opt/etc/nfqws2/lists/` |
| VPS для vless | свой / арендный конфиг |
