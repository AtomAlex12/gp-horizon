# AmneziaWG для WARP

Экспериментальная реализация для отдельного стенда Keenetic с Entware. Перед использованием на рабочем роутере нужно проверить переключение в обе стороны, поведение клиентского трафика и восстановление после перезагрузки на целевой версии KeeneticOS.

На стенде нужны совместимые с архитектурой роутера `amneziawg-go` и `awg`, а также `ip` с поддержкой policy routing, `ipset`, `iptables`, `curl` и `/dev/net/tun`. Поместите `warp-awg-device` из подписанного комплекта релиза в `/opt/libexec/nuxk/` с правами `0755`. Агент управляет этим скриптом сам.

Сгенерируйте профиль на машине с Warpscout. Профиль и файл аккаунта содержат ключи. Храните их в закрытом каталоге и переносите профиль на роутер по защищённому каналу.

```sh
umask 077
warpscout register
warpscout scan -p awg -P -conf warp-awg.conf
```

Сохраните профиль на роутере как `/opt/etc/nuxk/warp-awg.conf` с правами `0600`. Поддерживается один пир с IP endpoint, адресом туннеля IPv4 /32 и `0.0.0.0/0` в AllowedIPs. Настройки DNS и таблиц из профиля агент игнорирует. Профили с хуками запуска или остановки отклоняются.

В `nuxk.conf` укажите `WARP_AWG_DNS_ADDR` с IPv4-адресом самого стенда в LAN и отдельным свободным портом. Для пробы нужен действующий USQUE, `PLANE=keenetic` и `PLANE_APPLY=1`. В Horizon откройте **WARP → Транспорт**. Успешный переход записывается в существующий `plane.json`.

На AmneziaWG Keenetic направляет DNS-запросы из группы WARP к отдельному локальному обработчику Horizon. Он обновляет набор адресов Entware. Правила для `awg0` применяются к IPv4-пакетам без метки и к пакетам со стандартной меткой LAN Keenetic `0xffffaaa`. Режим рассчитан на клиентов с DNS Keenetic. Проверка из Horizon подтверждает Cloudflare WARP через `awg0`. Проверка на LAN-клиенте нужна отдельно, включая метку политики на целевой прошивке, переключение с заполненным DNS-кешем, работу VLESS и поведение IPv6.

При RCI HTTP 403 проверьте `PLANE_RCI` и права агента на локальный RCI. Пока проверки на стенде не пройдены, верните USQUE через панель перед удалением агента или откатом на версию, которая не умеет убирать привязки AmneziaWG.

При переходе на AmneziaWG скрипт USQUE выключает интерфейс, а агент снимает маршрут группы WARP. Объект `OpkgTunN` остаётся в KeeneticOS. На него могут ссылаться статические маршруты и политики, которых нет в списке DNS-маршрутов RCI.

При политике «блокировать при падении» агент отклоняет переключение на AmneziaWG до проверки безопасного переноса уже закешированных клиентами адресов. В режиме «напрямую» автоматический возврат на обычный маршрут происходит при исчезновении `awg0`. Отдельно нужно проверить случай, когда процесс жив, но туннель перестал передавать данные.
